# 신명호

**측정하지 않은 것은 도입하지 않고, 검증하지 않은 수치는 쓰지 않습니다.**
자동화를 늘리는 것보다 어디까지 자동화할 수 있는지 재는 데 더 많은 시간을 씁니다.

지적·공유재산 실무를 자동화하는 도구를 만들고, 그 위에 로컬 LLM을 올리고 있습니다.
목표는 QGIS를 자연어로 제어하는 전용 모델과 사내 프로젝트 전용 LLM입니다.

도구를 먼저 만들었고, 그 도구들을 파이프라인으로 묶은 뒤, 마지막에 LLM을 붙였습니다.
제어할 대상이 없으면 자연어 인터페이스는 쓸 곳이 없기 때문입니다.

```
LLM        자연어 → PyQGIS 실행 에이전트 · RAG 검색 · 모델 평가 하네스
파이프라인   12단계 상태 기반 오케스트레이터 · QGIS 소켓 브릿지 · 업무 DB
도구        QGIS 플러그인 5종 (정합 · 캡처 · 순회 · 지리참조 · 현장확인)
```

아래는 전부 설계·구현·테스트·사내 배포까지 1인 개발이며,
실제 지자체 실태조사 사업에 투입되어 팀 5명(본인 포함)이 사용 중입니다.

## AI / LLM

**로컬 모델 평가 하네스** · 한글, JSON, PyQGIS 세 축으로 케이스 36종을 구성해
후보 모델을 정확도와 속도로 실측하고 선정했습니다.
채점 과정에서 하네스 자체 결함 두 건(deprecated API를 정답으로 요구, JSON 강제 옵션의 빈 응답)을
먼저 찾아 고쳤습니다. 그대로 뒀다면 배관 문제를 모델 능력으로 오독할 뻔했습니다.

**RAG 검색 품질 개선** · 청킹 재설계를 A/B로 먼저 검증해 원인이 청킹이 아님을 확인한 뒤
임베딩 모델 3종을 비교하고 교체했습니다.
한국어 Recall@3 42% → 83%, MRR 0.39 → 0.80 (자체 평가셋 16문항).
프레임워크 없이 sentence-transformers와 SQLite, numpy로 직접 구성했습니다.
평가셋이 작아 과적합 위험이 있다는 것을 전제로 씁니다. 실제로 규칙 도출 쪽에서
한 지자체 데이터에 과적합된 규칙이 나온 적이 있고, 집계 단위를 행에서 사업으로
바꿔 재도출해 해소했습니다.

**자연어 실행 에이전트** · 자연어를 PyQGIS 코드로 생성하고 실행한 뒤,
실패하면 트레이스백을 되먹여 자가 수정합니다.
실행 실패의 원인이 모델 성능이 아니라 실행 스캐폴딩임을 실측으로 특정하고 프리앰블 주입으로 해결했습니다.
실무 벤치마크 7/8 → 8/8.

**적용 범위 판단** · 기능마다 LLM과 규칙과 사람을 실측 비교해 도입 여부를 정했습니다.
이미지 기반 판정은 VLM exact-match 8%로 부적합을 확인하고 스크리닝 용도로 축소했으며,
같은 데이터에서 도출한 규칙 한 건이 재현율 100%(208건)로 이를 대체했습니다.

반대 방향도 측정했습니다. 근거가 약한 채로 제가 직접 넣었던 규칙이 정밀도 37%로
전체 정확도를 깎고 있던 것을 오류 분석으로 찾아 제거해 84% → 88%로 올렸습니다.
남의 기술을 안 쓰기로 정하는 것보다, 내가 만든 것을 재서 죽이는 쪽이 어려웠습니다.

### [life-rag-system](https://github.com/ShinMyeongho/life-rag-system)

생활 데이터를 기록하면 Claude가 전문 문서를 근거로 분석해주는 개인용 웹 애플리케이션입니다.
하이브리드 검색(FAISS + BM25 + Cross-encoder)과 한국어 임베딩을 직접 구성했고, pytest로 검증했습니다.

`Streamlit` `MySQL` `Claude API` `FAISS` `BM25` `Cross-encoder` `Docker` `pytest`

위 실무 RAG 작업은 이 프로젝트에서 하이브리드 검색을 직접 만들어 본 경험 위에서 진행했습니다.

## GIS 업무 자동화

전국 지자체 공유재산 실태조사 업무에서 반복되던 작업을 도구로 옮겼습니다.
사내 플러그인 저장소를 만들어 배포하고, 버전과 금지 파일 검사를 배포 스크립트로 강제합니다.

| 도구 | 하는 일 | 남긴 것 |
|---|---|---|
| **[드론 사진 지리참조](https://github.com/ShinMyeongho/jpg-to-tif-portfolio)** | 드론 JPG의 GPS·짐벌 정보를 읽어 위성영상과 대조하고 지적도에 정합된 GeoTIFF로 변환 | 매칭 경로를 딥러닝 매처 우선, 특징점 매칭 폴백 구조로 재편해 1패스 자동 확정률 19% → 60% (사업지 2곳, 1,088장 실측) |
| **필지 캡처** | 조사 대상 필지 단위로 근경·원경·위성·지적 4컷을 규격에 맞춰 일괄 렌더 | 손상된 영상을 색인 전에 걸러내 표본 오염 80% 제거 |
| **[필지 순회 콘솔](https://github.com/ShinMyeongho/pnu-navigator-portfolio)** | 대상 목록을 순회하며 확인 결과를 기록 | 사업별 설정을 프로젝트 파일 옆 사이드카로 분리해 팀원이 프로젝트만 열면 동작 |
| **지리참조 편집기** | 자동 정합이 실패한 사진을 직접 맞추는 도구 | 지상기준점 기반 유사변환을 최소제곱 닫힌해로 직접 구현, 단위테스트 27건 |
| **업무 파이프라인** | 12단계 업무를 상태 기반 DAG로 정의하고 도구들을 단계 핸들러로 연결 | 회귀 테스트 287건, 종료 코드만 보고 실패를 완료로 보고하던 결함 수정 |

링크된 두 저장소는 공개본입니다. 사업별 설정과 고객 데이터, 원본 사진을 제외하고
코드와 설계 근거만 담았습니다. 발주처는 명시하지 않았고 표본 파일명은 익명화했으나,
지역을 구분해야 설명이 되는 실측 사례에는 읍·면·동 지명이 남아 있습니다.
개발은 로컬에서 진행하므로 공개본은 스냅샷입니다.

나머지 도구는 업무 산출물이 섞여 있어 공개하지 않습니다.
