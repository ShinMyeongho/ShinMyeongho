# 포트폴리오 허브(GitHub 프로필 README) 설계

- 날짜: 2026-07-18
- 대상: `github.com/ShinMyeongho/ShinMyeongho` (GitHub 프로필 README 저장소)

## 배경

신명호(34세, 법학과 중퇴, 전산회계 1급)는 현재 (주)아이티코리아 재산정보팀
소속으로 지적·공유재산 실태조사 업무를 하며, 개발 직무는 아니지만 입사 후
약 1.5개월 만에 AI 코딩 도구(Claude Code)를 활용해 실무 자동화 도구 3종을
직접 설계·개발했다. 이전 경력(스피링크/한수원 생성형 AI 프로젝트, 데이터메이커
프리랜서)은 데이터 라벨링·품질관리·RAGAS 평가·프롬프트 엔지니어링 중심이며,
이력서에는 코딩/개발 경력이 전혀 드러나지 않는다.

목표 직무는 아직 확정하지 않았고, AI/ML 엔지니어 트랙과 GIS·지적업무 자동화
트랙 둘 다 열어두고 지원할 계획이다. 포트폴리오 허브는 "비개발 직군이지만
실무 문제를 스스로 자동화 도구로 풀어온 사람"이라는 통합 서사로 두 트랙을
모두 뒷받침해야 한다.

2026-07-18 세션에서 후보 4개 저장소 전체를 감사해 실사용 버그를 발견·TDD로
수정·push까지 검증 완료했다 (자세한 내용은 각 저장소 커밋 로그 및
`itk_Qgis/docs/2026-07-18-personal-pc-debugging-session.md` 참고).

## 포트폴리오 후보 4개 저장소

| 저장소 | 현재 공개 상태 | 트랙 | 한 줄 요약 |
|---|---|---|---|
| `life-rag-system` | PUBLIC | AI/ML | Streamlit + MySQL + Hybrid RAG(FAISS+BM25+Cross-encoder) + Claude API 개인 일지 앱. 162 테스트. 이미 완성된 포트폴리오(이력서에 이미 링크됨). |
| `jpg-to-tif` | PRIVATE | AI/ML **+** GIS | QGIS 플러그인. 드론 JPG를 GPS/XMP/DEM/자기편차보정/위성NCC/LoFTR(딥러닝 이미지매칭)/클러스터모자이크정합으로 GeoTIFF 변환. 95+ 커밋. 오늘 데드락 등 진짜 버그 5건 수정(v1.39). |
| `pnu-navigator` | PRIVATE | GIS | QGIS 플러그인. PNU 목록 순회하며 필지 확인·기록, 실제 현장에서 사용. 84 커밋. 오늘 편집세션 유실(조사결과 미저장) 등 버그 4건 수정. |
| `basic-survey-automation` | PRIVATE | GIS | Kakao/VWorld/TAGO API로 실태조사 엑셀 자동 채움, 팀 배포판. 오늘 행 정렬 유실·캐시 오염 등 버그 5건 수정. |

`itk_Qgis`(세션 간 조사노트 저장소)는 허브 대상에서 제외 — 포트폴리오용
산출물이 아니라 개인 작업 기록용.

## 형식 결정

- **GitHub 프로필 README** (`github.com/ShinMyeongho/ShinMyeongho` 저장소의
  `README.md`) — 방문 시 자동 노출, 별도 호스팅/유지보수 불필요.
- **한국어만.** 목표 채용시장이 대전·서울·충남 지역 국내 채용이라 한국어로
  충분하고, 이중언어 유지보수 부담을 피한다.

## 구조

섹션을 두 트랙으로 분리한다 (하나의 기술 난이도순 리스트가 아니라):

1. **짧은 자기소개** — "비개발 직군이지만 AI 코딩 도구로 실무 자동화 도구를
   직접 만들고 유지보수한다"는 서사. 이력서 자기소개서에 추가한 문단과
   톤을 맞춘다.
2. **AI/ML 트랙** — `life-rag-system`(먼저, 완성도 높음), `jpg-to-tif`의
   LoFTR/딥러닝 매칭 부분을 강조.
3. **GIS·지적업무 자동화 트랙** — `pnu-navigator`, `basic-survey-automation`,
   `jpg-to-tif`의 드론 정합/DEM 진단 부분을 강조.
4. 각 프로젝트 블록 구성: 한 줄 설명 + 기술스택 + "실제로 어떤 문제를
   풀었나" 한 문단 + 저장소 링크.

`jpg-to-tif`는 두 트랙 모두에 노출된다(같은 저장소, 다른 강조점).

## 콘텐츠 원칙

- **검증 안 된 수치는 쓰지 않는다.** 이력서 작업 때와 동일한 원칙 — 정확한
  성과 지표(처리 건수, 정확도 개선율 등)를 모르면 지어내지 않고, "실제로
  동작하는 도구를 만들고 자동화 테스트로 검증했다"는 사실 기반 서술로 대신한다.
- 각 프로젝트가 "실제로 어떤 문제를 풀었는지"를 구체적으로 쓴다 (예:
  jpg-to-tif의 DEM 90m 해상도 한계 진단, pnu-navigator의 편집세션 유실
  버그처럼 오늘 세션에서 확인한 실제 사례 활용 가능).

## 공개 전환 절차 (공개 시점: 전부 준비된 후 한 번에)

1. 각 저장소 README를 이 설계에 맞춰 작성 (저장소는 비공개 상태로 작업)
2. **`pnu-navigator` 민감정보 처리** — `settings.json`에 실제 고객 업무 맥락
   (예: "2026_무단점유_확인", 세종/천안 프로젝트명)이 들어있음. 공개 전
   `jpg-to-tif`의 `worker_db.json` 스크럽과 동일한 절차로 처리
   (더미화 또는 `.gitignore` 처리 + 필요시 히스토리 스크럽) 필요.
   `jpg-to-tif`, `basic-survey-automation`은 이미 이번 세션에서 점검
   완료(전자는 스크럽 완료, 후자는 원래 클린).
3. 프로필 README(허브) 작성
4. 전부 확인되면 저장소 3개(`jpg-to-tif`, `pnu-navigator`,
   `basic-survey-automation`) 공개 전환 → 프로필 README 공개(`ShinMyeongho`
   저장소 생성·push)
